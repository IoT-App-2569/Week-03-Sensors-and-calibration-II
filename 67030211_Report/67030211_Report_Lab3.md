### ส่วนที่ 1.6 — ตารางคำนวณแรงดันเอาต์พุตจากวงจร

คำนวณจากสูตร $V_{out} = V_{cc} \times \frac{R_{fixed}}{R_{LDR} + R_{fixed}}$ โดย $V_{cc} = 3.3\text{V}$ และ $R_{fixed} = 10\text{ k}\Omega$:

| สภาพแสง | ความต้านทาน LDR | แรงดันเอาต์พุตที่คำนวณได้ | แรงดันประมาณ (V) |
| :--- | :---: | :---: | :---: |
| **มืดสนิท** | $200\text{ k}\Omega - 2\text{ M}\Omega$ | $3.3 \times \frac{10}{200+10} = 0.16\text{V}$ ถึง $0.02\text{V}$ | **0 V** |
| **ห้องปกติ** | $10\text{ k}\Omega - 50\text{ k}\Omega$ | $3.3 \times \frac{10}{10+10} = 1.65\text{V}$ ถึง $0.55\text{V}$ | **1 V – 2 V** |
| **ใต้โคมไฟ** | $2\text{ k}\Omega - 10\text{ k}\Omega$ | $3.3 \times \frac{10}{2+10} = 2.75\text{V}$ ถึง $1.65\text{V}$ | **2 V – 3 V** |
| **กลางแจ้ง** | $200\Omega - 2\text{ k}\Omega$ | $3.3 \times \frac{10}{0.2+10} = 3.24\text{V}$ ถึง $2.75\text{V}$ | **3 V** |

### ส่วนที่ 3 — โค้ด ESP-IDF สำหรับอ่านค่า ADC ดิบ

```c
#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/adc.h"
#include "esp_log.h"

#define ADC_CHANNEL     ADC1_CHANNEL_6   // GPIO34
#define ADC_ATTEN       ADC_ATTEN_DB_11  // รองรับ ~3.3V
#define ADC_WIDTH       ADC_WIDTH_BIT_12 // 0–4095

void app_main(void)
{
    adc1_config_width(ADC_WIDTH);
    adc1_config_channel_atten(ADC_CHANNEL, ADC_ATTEN);

    printf("Start Reading LDR Raw ADC...\n");

    while (1) {
        int raw = adc1_get_raw(ADC_CHANNEL);
        printf("ADC Raw = %d\n", raw);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

```text
ADC Raw = 1800

ADC Raw = 3500
```

### ส่วนที่ 5 — การทำกราฟเพื่อหาสมการ

นำข้อมูลไปพล็อตกราฟ Scatter Plot ใน Excel และเพิ่มเส้นแนวโน้ม (Trendline):

1. **แบบเส้นตรง (Linear):**
   * สมการ: $\text{Lux} = 0.3537 \times \text{ADC} - 208.59$
   * ค่า $R^2 = 0.9157$
   * ข้อสังเกต: ช่วงแสงน้อย (ADC < 590) คำนวณได้ค่าติดลบ ซึ่งไม่ตรงกับความเป็นจริง

2. **แบบเส้นโค้งพหุนาม (Polynomial ดีกรี 2):**
   * สมการ: $\text{Lux} = 0.000112 \times \text{ADC}^2 - 0.0602 \times \text{ADC} + 28.92$
   * ค่า $R^2 = 0.9979$
   * ข้อสังเกต: กราฟแนบสนิทกับจุดข้อมูลจริงได้ดีกว่าแบบเส้นตรงมาก สอดคล้องกับคุณสมบัติของ LDR

**สรุป:** เลือกใช้สมการ **Polynomial** ในการเขียนโปรแกรม เนื่องจากค่า $R^2$ สูงกว่าอย่างชัดเจน

### ส่วนที่ 6 — โค้ด ESP-IDF แสดงผล Lux แบบเรียลไทม์

```c
#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/adc.h"
#include "esp_log.h"

#define ADC_CHANNEL     ADC1_CHANNEL_6
#define ADC_ATTEN       ADC_ATTEN_DB_11
#define ADC_WIDTH       ADC_WIDTH_BIT_12

int adc_to_lux(int adc)
{
    if (adc <= 280) return 0;
    
    // คำนวณจากสมการ: Lux = 0.000112 * ADC^2 - 0.0602 * ADC + 28.92
    float lux = (0.000112f * adc * adc) - (0.0602f * adc) + 28.92f;
    if (lux < 0.0f) lux = 0.0f;
    
    return (int)(lux + 0.5f);
}

void app_main(void)
{
    adc1_config_width(ADC_WIDTH);
    adc1_config_channel_atten(ADC_CHANNEL, ADC_ATTEN);

    printf("--- ESP32 LDR Lux Meter Ready ---\n");

    while (1) {
        int raw_adc = adc1_get_raw(ADC_CHANNEL);
        int lux = adc_to_lux(raw_adc);

        printf("ADC = %d | Lux = %d lx\n", raw_adc, lux);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

```text

ADC = 500  | Lux = 27 lx
ADC = 1200 | Lux = 118 lx
ADC = 1800 | Lux = 284 lx
ADC = 2500 | Lux = 578 lx
ADC = 3500 | Lux = 1190 lx
```

### ส่วนที่ 7 — การทดสอบความแม่นยำกับจุดแสงใหม่ 3 จุด

ทดสอบวัดแสงในตำแหน่งใหม่ที่ไม่ได้ใช้ในขั้นตอนการสร้างสมการ:

$$\text{Absolute Error } = |\text{Lux}_{calc} - \text{Lux}_{phone}|$$

$$\% \text{Error} = \frac{|\text{Lux}_{calc} - \text{Lux}_{phone}|}{\text{Lux}_{phone}} \times 100\%$$

| สภาพแสงที่ทดสอบใหม่ | ค่า ADC | Lux จากมือถือ | Lux จากโค้ด | Absolute Error | % Error |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **ซอกหลังตู้หนังสือ** | 600 | **45** | **33** | **12 lx** | 26.5% |
| **หน้าจอคอมพิวเตอร์** | 1500 | **200** | **190** | **10 lx** | 4.8% |
| **ขอบระเบียงห้อง** | 2800 | **700** | **738** | **38 lx** | 5.4% |

**วิเคราะห์ผล:**
* ในช่วงแสงระดับกลางถึงสว่าง (200–700 Lux) ความคลาดเคลื่อนต่ำมากอยู่ที่ประมาณ 4.8%–5.4%
* ในช่วงที่มืดมาก (45 Lux) มี % Error สูงขึ้นเนื่องจากขีดจำกัดความไวของเซนเซอร์กล้องมือถือในที่มืด แต่ระดับตัวเลขยังจัดอยู่ในเกณฑ์จำแนกระดับแสงได้แม่นยำ

### ส่วนที่ 8 — คำตอบคำถามท้ายใบงาน

#### 1. ทำไมต้องใช้ Voltage Divider ในการอ่าน LDR?
**ตอบ:** ไมโครคอนโทรลเลอร์อ่านได้เฉพาะระดับแรงดันไฟฟ้า แต่ไม่สามารถวัดค่าความต้านทานตรงๆ ได้ จึงต้องต่อ Voltage Divider ร่วมกับตัวต้านทานคงที่ เพื่อแปลงค่าความต้านทานของ LDR ให้เป็นระดับแรงดันไฟฟ้าส่งเข้าขา ADC

#### 2. ทำไมต้องเก็บข้อมูลหลายจุดก่อนทำ Calibration?
**ตอบ:** ความสัมพันธ์ระหว่างความต้านทานของ LDR กับความเข้มแสงเป็นแบบไม่เชิงเส้น (Non-linear) หากเก็บข้อมูลเพียง 2 จุด เส้นแนวโน้มที่ได้จะเป็นเส้นตรงซึ่งคลาดเคลื่อนจากพฤติกรรมจริง การเก็บข้อมูล 5–7 จุด ทำให้สร้างสมการแบบ Polynomial ที่ตรงกับพฤติกรรมจริงได้แม่นยำกว่า

#### 3. ถ้า Noise มากกว่าสัญญาณจริง จะเกิดอะไรขึ้น?
**ตอบ:** ข้อมูลที่อ่านได้จะผันผวนและไม่นิ่ง ข้อมูลกระโดดขึ้นลง ทำให้ระบบประมวลผลผิดพลาด และสั่งการทำงานผิดพลาด เช่น หลอดไฟในระบบเปิดปิดอัตโนมัติติดดับสลับไปมาอย่างต่อเนื่อง

#### 4. ทำไมการวางตำแหน่งเซนเซอร์จึงสำคัญต่อ Signal Integrity?
**ตอบ:** หากวางเซนเซอร์ใกล้แหล่งกำเนิดสัญญาณรบกวน เช่น มอเตอร์ หม้อแปลง หรือเสาอากาศ จะมีสัญญาณรบกวนเหนี่ยวนำเข้าสู่วงจร และหากวางในมุมที่มีสิ่งกีดขวางหรือเงาบัง แสงที่ตกกระทบจะไม่ตรงกับสภาพแวดล้อมจริง

#### 5. ถ้า ADC มี Resolution ต่ำ จะส่งผลอย่างไรต่อความแม่นยำ?
**ตอบ:** การแบ่งระดับแรงดันจะมีขั้นบันไดที่หยาบ ทำให้ไม่สามารถตรวจจับการเปลี่ยนแปลงของแรงดันขนาดเล็กได้ ค่าความสว่างที่ต่างกันเล็กน้อยจะอ่านได้เป็นค่า ADC เดียวกัน ส่งผลให้ความละเอียดและความแม่นยำลดลง

1. **จุดไหนในใบงานที่คิดว่ายากที่สุด?**
