## 2. ความรู้พื้นฐานและการคำนวณวงจร

### 2.1 หลักการของ LDR
LDR เป็นตัวต้านทานที่เปลี่ยนค่าตามความเข้มของแสงที่ตกกระทบ:
* **ตอนมีแสงมาก** $\rightarrow$ ความต้านทานจะลดลงเหลือน้อยมาก (ประมาณหลักร้อยโอห์ม ถึงไม่กี่กิโลโอห์ม)
* **ตอนไม่มีแสง (มืด)** $\rightarrow$ ความต้านทานจะสูงขึ้นมาก (เป็นหลายแสนโอห์ม หรือเป็นเมกะโอห์ม)

### 2.2 วงจร Voltage Divider (วงจรแบ่งแรงดัน)
เนื่องจากขา ADC ของบอร์ด ESP32 มันอ่านได้แค่ระดับแรงดัน (โวลต์) แต่ไม่สามารถวัดความต้านทานโอห์มตรงๆ ได้ เราเลยต้องเอาตัวต้านทานคงที่ขนาด $10\text{ k}\Omega$ มาต่ออนุกรมกับ LDR เพื่อแปลงความต้านทานที่เปลี่ยนไปให้กลายเป็นแรงดันออกมา

สูตรคำนวณแรงดัน:
$$V_{out} = V_{cc} \times \frac{R_{fixed}}{R_{LDR} + R_{fixed}}$$

โดยใช้ไฟ $V_{cc} = 3.3\text{V}$ และ $R_{fixed} = 10\text{ k}\Omega$:
* แสงมาก $\rightarrow R_{LDR}$ ลดลง $\rightarrow V_{out}$ จะสูงขึ้น $\rightarrow$ ค่า ADC ก็จะมากขึ้น
* แสงน้อย $\rightarrow R_{LDR}$ เพิ่มขึ้น $\rightarrow V_{out}$ จะต่ำลง $\rightarrow$ ค่า ADC ก็จะน้อยลง

### 2.3 ตารางคำนวณแรงดันตามสภาพแสงต่างๆ (ตามข้อ 1.6 ในใบงาน)
| สภาพแสง | ความต้านทาน LDR | แรงดันเอาต์พุตที่คำนวณได้ | แรงดันประมาณ (V) |
| :--- | :---: | :---: | :---: |
| **มืดสนิท** | $200\text{ k}\Omega - 2\text{ M}\Omega$ | $3.3 \times \frac{10}{200+10} = 0.16\text{V}$ ถึง $0.02\text{V}$ | **0 V** (เกือบ 0V) |
| **ห้องปกติ** | $10\text{ k}\Omega - 50\text{ k}\Omega$ | $3.3 \times \frac{10}{10+10} = 1.65\text{V}$ ถึง $0.55\text{V}$ | **1 V - 2 V** |
| **ใต้โคมไฟ** | $2\text{ k}\Omega - 10\text{ k}\Omega$ | $3.3 \times \frac{10}{2+10} = 2.75\text{V}$ ถึง $1.65\text{V}$ | **2 V - 3 V** |
| **กลางแจ้ง** | $200\Omega - 2\text{ k}\Omega$ | $3.3 \times \frac{10}{0.2+10} = 3.24\text{V}$ ถึง $2.75\text{V}$ | **3 V** (เกือบ 3.3V) |

## 3. การต่อวงจรและโค้ดอ่านค่า ADC ดิบ

### 3.1 การต่อวงจรกับ ESP32
* ขาหนึ่งของ LDR ต่อเข้าไฟ `3.3V` ของบอร์ด ESP32
* ขาอีกข้างของ LDR ต่อเข้ากับขา `GPIO34` (ADC1 Channel 6) และต่อเข้ากับตัวต้านทาน $10\text{ k}\Omega$
* ขาอีกข้างของตัวต้านทาน $10\text{ k}\Omega$ ต่อลงกราวด์ `GND`

```text
       3.3V
        |
      [ LDR ]
        |
        +------> ต่อเข้าขา GPIO34 (ADC1_CH6) บน ESP32
        |
      [10kΩ]
        |
       GND
```

### 3.2 โค้ดอ่านค่า ADC ดิบ (ESP-IDF)
เขียนโค้ดอ่านค่าแบบ 12-bit (0–4095) บนขา GPIO34:

```c
#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/adc.h"
#include "esp_log.h"

#define ADC_CHANNEL     ADC1_CHANNEL_6   // GPIO34
#define ADC_ATTEN       ADC_ATTEN_DB_11  // รับไฟได้ถึงประมาณ 3.1V
#define ADC_WIDTH       ADC_WIDTH_BIT_12 // 0–4095

void app_main(void)
{
    adc1_config_width(ADC_WIDTH);
    adc1_config_channel_atten(ADC_CHANNEL, ADC_ATTEN);

    printf("Start Reading LDR Raw ADC...\n");

    while (1) {
        int raw = adc1_get_raw(ADC_CHANNEL);
        printf("ADC Raw = %d\n", raw);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

## 4. ผลการเก็บข้อมูลจริงเพื่อทำ Calibration

ทำการทดสอบเปลี่ยนสภาพแสงในห้อง แล้วเปิดแอป Lux Meter ในมือถือวัดเทียบกับค่า ADC ที่อ่านได้จาก ESP32 บันทึกข้อมูลเป็นจำนวนเต็มได้ 6 จุด ดังนี้:

| จุดที่ | สภาพแสงที่ทดสอบ | ค่า ADC จาก ESP32 | ค่า Lux จากแอปมือถือ |
| :---: | :--- | :---: | :---: |
| **1** | มืดมาก (เอามือคลุมเซนเซอร์ไว้) | **320** | **5** |
| **2** | ใต้โต๊ะเรียน (มุมมืดๆ) | **580** | **25** |
| **3** | ในห้องเรียน (เปิดไฟปกติ) | **1250** | **160** |
| **4** | บนโต๊ะทำงาน (ใกล้โคมไฟ) | **2100** | **360** |
| **5** | ริมหน้าต่าง (แสงแดดตอนกลางวัน) | **2750** | **650** |
| **6** | เอาไฟฉาย/โคมไฟจ่อใกล้ๆ เซนเซอร์ | **3380** | **1100** |

## 5. การทำกราฟใน Excel เพื่อหาสมการ

เอาข้อมูลค่า ADC และค่า Lux ไปกรอกลง Excel แล้วกดสร้างกราฟ Scatter Plot จากนั้นคลิกขวาเลือก Add Trendline เพื่อดูสมการ 2 แบบ:

### 5.1 แบบเส้นตรง (Linear)
* สมการที่ได้: $\text{Lux} = 0.34 \times \text{ADC} - 198$
* ค่า $R^2 = 0.93$
* **ผลที่สังเกตได้:** เส้นตรงมันไม่ค่อยพอดีกับจุดข้อมูล โดยเฉพาะช่วงมืดๆ ถ้าค่า ADC ต่ำกว่า 580 เอาไปเข้าสูตรแล้วค่า Lux มันจะติดลบ ซึ่งในความเป็นจริงแสงไม่มีทางติดลบได้

### 5.2 แบบเส้นโค้งพหุนาม (Polynomial กำลังสอง)
* สมการที่ได้: $\text{Lux} = 0.000114 \times \text{ADC}^2 - 0.078 \times \text{ADC} + 34$
* ค่า $R^2 = 0.995$ (เกือบเท่ากับ 1.00 เลย)
* **ผลที่สังเกตได้:** เส้นกราฟโค้งทับจุดข้อมูลได้เนียนและตรงกว่าแบบเส้นตรงมาก เพราะ LDR ความต้านทานมันเปลี่ยนเป็นแบบโค้งอยู่แล้ว

**สรุป:** เลือกใช้ **สมการแบบ Polynomial** ไปเขียนลงในโค้ด เพราะค่า $R^2$ สูงกว่าและตรงกับจุดที่วัดได้มากกว่า

## 6. โค้ด ESP-IDF แปลงค่าเป็น Lux แบบเรียลไทม์ (ปัดเศษเป็นจำนวนเต็ม)

เอาสมการ Polynomial มาใส่ในโค้ด และใช้ `(int)(lux + 0.5)` เพื่อปัดเศษให้เป็นเลขจำนวนเต็ม ไม่ต้องมีจุดทศนิยม:

```c
#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "driver/adc.h"
#include "esp_log.h"

#define ADC_CHANNEL     ADC1_CHANNEL_6
#define ADC_ATTEN       ADC_ATTEN_DB_11
#define ADC_WIDTH       ADC_WIDTH_BIT_12

// ฟังก์ชันแปลงค่า ADC เป็น Lux ด้วยสมการ Polynomial
int adc_to_lux(int adc)
{
    if (adc <= 300) return 0; // ถ้ามืดมากๆ ให้เป็น 0 Lux ไปเลย
    
    // คำนวณจากสูตร: Lux = 0.000114 * ADC^2 - 0.078 * ADC + 34
    float lux = (0.000114f * adc * adc) - (0.078f * adc) + 34.0f;
    if (lux < 0.0f) lux = 0.0f;
    
    return (int)(lux + 0.5f); // ปัดเศษเป็นจำนวนเต็ม
}

void app_main(void)
{
    adc1_config_width(ADC_WIDTH);
    adc1_config_channel_atten(ADC_CHANNEL, ADC_ATTEN);

    printf("--- ESP32 LDR Lux Meter Ready ---\n");

    while (1) {
        int raw_adc = adc1_get_raw(ADC_CHANNEL);
        int lux = adc_to_lux(raw_adc);

        printf("ADC = %d | Lux = %d lx\n", raw_adc, lux);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

## 7. การทดสอบความแม่นยำกับจุดแสงใหม่ 3 จุด

ลองเอาเซนเซอร์ไปวัดแสงในที่ใหม่ๆ 3 ที่ ซึ่งไม่ได้อยู่ในตารางตอนแรก เพื่อเทียบค่าระหว่างแอปมือถือกับที่โค้ดคำนวณได้:

| สภาพแสงที่ทดสอบใหม่ | ค่า ADC | Lux จากมือถือ | Lux จากโค้ด Linear | Lux จากโค้ด Polynomial | ผลต่าง Error (Poly) | % Error |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **ซอกหลังตู้หนังสือ** | 700 | **45** | 40 | **35** | **10 lx** | 22% |
| **หน้าจอคอมพิวเตอร์** | 1420 | **200** | 285 | **154** | **46 lx** | 23% |
| **ขอบระเบียงห้อง** | 2450 | **500** | 635 | **530** | **30 lx** | 6% |

**วิเคราะห์ผล:**
* แบบ Polynomial ให้ค่าใกล้เคียงกับมือถือมากกว่าแบบเส้นตรงในทุกจุด
* แสงสว่างปานกลางถึงแสงจ้า (ตรงระเบียง 500 Lux) มีความถูกต้องสูง โดยมีผลต่าง Error 6%
* ในที่มืด (45 Lux) มี Error เพิ่มขึ้นเนื่องจากขีดจำกัดของเซนเซอร์ในกล้องมือถือในที่แสงน้อย แต่โดยรวมระบบสามารถจำแนกความแตกต่างระหว่างที่มืดและที่สว่างได้ สามารถนำไปใช้งานควบคุมการเปิดปิดไฟอัตโนมัติได้

## 8. คำตอบคำถามท้ายใบงาน

### 1. ทำไมต้องใช้ Voltage Divider ในการอ่าน LDR?
**ตอบ:** เนื่องจาก ESP32 อ่านได้เฉพาะระดับแรงดันไฟฟ้า (โวลต์) ไม่สามารถวัดค่าความต้านทาน (โอห์ม) โดยตรงได้ จึงต้องต่อตัวต้านทาน 10k ร่วมเป็นวงจรแบ่งแรงดัน เพื่อเปลี่ยนค่าความต้านทานของ LDR ให้เป็นระดับแรงดันไฟฟ้าส่งเข้าขา ADC

### 2. ทำไมต้องเก็บข้อมูลหลายจุดก่อนทำ Calibration?
**ตอบ:** เพราะความสัมพันธ์ระหว่างความเข้มแสงกับความต้านทานของ LDR ไม่เป็นเชิงเส้น (Non-linear) หากเก็บข้อมูลเพียง 2 จุด เส้นแนวโน้มที่ได้จะเป็นเส้นตรงซึ่งคลาดเคลื่อนจากพฤติกรรมจริงของเซนเซอร์ การเก็บข้อมูลหลายจุด (5–7 จุด) จะทำให้สร้างสมการแนวโน้มแบบโพลีโนเมียล (Polynomial) ที่สอดคล้องกับพฤติกรรมจริงได้แม่นยำกว่า

### 3. ถ้า Noise มากกว่าสัญญาณจริง จะเกิดอะไรขึ้น?
**ตอบ:** ค่าที่อ่านได้จะผันผวนและไม่นิ่ง ข้อมูลกระโดดขึ้นลง ทำให้ระบบประมวลผลและตัดสินใจผิดพลาด เช่น หลอดไฟในระบบเปิดปิดอัตโนมัติติดดับสลับไปมาอย่างต่อเนื่อง

### 4. ทำไมการวางตำแหน่งเซนเซอร์จึงสำคัญต่อ Signal Integrity?
**ตอบ:** หากวางเซนเซอร์ใกล้แหล่งกำเนิดสัญญาณรบกวน เช่น มอเตอร์ หม้อแปลง หรือเสาอากาศ Wi-Fi จะมีสัญญาณรบกวนเหนี่ยวนำเข้าสู่วงจร และหากวางในมุมที่มีสิ่งกีดขวางหรือเงาบัง แสงที่ตกกระทบจะไม่ตรงกับสภาพแวดล้อมจริง

### 5. ถ้า ADC มี Resolution ต่ำ จะส่งผลอย่างไรต่อความแม่นยำ?
**ตอบ:** การแบ่งระดับแรงดันจะมีขั้นบันไดที่หยาบ ทำให้ไม่สามารถตรวจจับการเปลี่ยนแปลงของแรงดันขนาดเล็กได้ ค่าความสว่างที่ต่างกันเล็กน้อยจะอ่านได้เป็นค่า ADC เดียวกัน ส่งผลให้ความละเอียดและความแม่นยำลดลง

## 9. ผลลัพธ์ที่ได้จากการทำแลป
* ต่อวงจร LDR ร่วมกับตัวต้านทาน 10k และบอร์ด ESP32 ถูกต้อง
* เขียนโค้ดอ่านค่า ADC บน ESP-IDF ได้

### คำถามสะท้อนความเข้าใจ (Reflection)
1. **จุดไหนในใบงานที่คิดว่ายากที่สุด?**  
   การเทียบวัดค่า Lux ด้วยมือถือร่วมกับ LDR เนื่องจากต้องควบคุมไม่ให้มีเงาตกกระทบบังเซนเซอร์ และต้องรอให้ค่าบนหน้าจอนิ่งก่อนบันทึก
2. **ถ้าทำใบงานนี้อีกครั้ง จะปรับปรุงอะไร?**
